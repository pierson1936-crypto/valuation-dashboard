## 项目概况

这是一个本地运行的 A 股、ETF 和指数分析台。后端使用 Python 标准库
`ThreadingHTTPServer`，前端 HTML/CSS/JavaScript 内嵌在 `app.py`，图表使用 ECharts。
Web 核心按需读取腾讯、东方财富和新浪公开数据；独立盯盘模块使用本地 SQLite。

当前主要能力：

- 大盘、板块、自选分组和单标的分析；
- 行业资金净额使用同花顺免费源为主、东方财富完整结果回退，并保留最近完整快照；大盘页
  以净流入/净流出 TOP 8 对称柱状图和四类行业数量环形图展示资金结构；
- PE/PB/价格历史分位、K 线、技术指标、财务、资金流、风险报告和 Excel 导出；
- 单标的当日分时与参考指数相对强弱，包括均价和成交量；
- 单标的 K 线提供互斥的“K线结构”和“筹码结构”按需视图；K 线结构覆盖严格箱体与保守
  价格行为回退，普通股票还可显示本地估算成本密集区和简化筹码分布，ETF 不做筹码估算；
- 个股日内概况与公司定位，包括量比、换手、三级行业、主营和概念；
- 单标的按需 AI 独立分析和开放式大盘复盘：模型自行选择重点，但事实引用由后台核验；
- 本地自选盯盘、三线规则、异动事件和 Server酱/企业微信通知适配；
- 持仓截图拖入、千问视觉识别、人工校对和本地持仓保存；
- 无 Key、0 Token 的持仓组合扫描和无前视历史诊断重放；
- 可选 DeepSeek/GPT 两阶段持仓报告、自由判断对照和最近 7 次成功报告复盘；
- 可选 DeepSeek AI 助手、规则草案、事件复核和多股对比；旧多维分析只保留后端
  兼容接口，页面入口已经下线。

项目没有券商账户连接、自动交易或收益预测能力。分钟盯盘只运行确定性规则，不调用
大模型。

## 代码与数据入口

- `app.py`：网页、HTTP API、市场数据抓取、核心计算和内嵌前端；
- `agent.py`：命令行 AI 助手兼容入口；
- `monitor.py`：盯盘 CLI 兼容入口；
- `monitoring/`：SQLite 仓储、规则、后台服务、通知、截图识别和持仓报告；
- `data/monitor.db`：用户真实自选、持仓、规则、事件和报告状态，不得删除或用于测试；
- `tests/`：固定样例和临时数据库测试，不访问真实凭据。

网页默认地址为 `http://127.0.0.1:8688/`。页面 DeepSeek/OpenAI Key、DeepSeek
Flash/Pro 选择和千问配置保存在浏览器本地，不写入仓库或 SQLite；不同浏览器标签或
上下文可能显示不同设置。后端只接受 `deepseek-v4-flash` 与 `deepseek-v4-pro`。

## 当前准确状态

已实现：

- 单标的“分析报告”可按需调用 DeepSeek：模型从编号原始事实中自行选择 2 至 5 个重点、
  安排顺序和形成判断；已有规则报告折叠保留为不调用模型的数据底稿；
- 大盘 AI 报告不再套固定栏目，由模型从当前指数和板块涨跌中自行识别主要结构与矛盾；
  两类报告都拒绝不存在的事实编号，并可在页面查看实际引用的数据；
- 行业资金净额当前以同花顺为主源、东方财富完整结果为回退源；两者失败时优先保留最近
  完整快照。页面明确显示实际 `flow_label`，不会把同花顺净额伪装成东方财富主力净流入；
- 大盘资金结构使用净流出/净流入 TOP 8 对称柱和四类行业数量环图；快照过期只显示黄色
  提示，不再灰化整个行业涨跌区。完整行业榜仍按涨幅从高到低折叠展示；
- 单标的页面按需读取截至查询时点的当日分钟行情，与参考指数按昨收归一比较；股票按所属
  市场选择参考指数，ETF 优先通用匹配公开跟踪指数，匹配失败时回退沪深 300；
- 分时只覆盖当日，不含历史分钟数据、复杂形态、龙头股组合或盘中买卖提示。AI 只接收
  分时摘要和最多 8 个代表时点，不接收整条分钟序列；买一/卖一和布林带展示已撤下；
- K 线区域默认不请求关键位。点击“K线结构”后先识别严格震荡箱体；无箱体时保守显示
  上行/下行/震荡过渡状态、20 日位置、HH/HL/LH/LL 波段点、近期突破状态和观察区，
  观察区不冒充确认支撑压力。再次点击当前按钮恢复原始 K 线；
- 普通股票可切换“筹码结构”，优先读取东方财富前复权日 K 与换手率，失败时回退
  Baostock，再由本地模型估算主要成本密集区和简化筹码条；不再突出 70%成本区或估算
  获利占比。它不是客户端筹码成品或真实账户持仓，不进入风险评分、盯盘或买卖建议；
- 持仓截图、持仓行情、个股盘口概念、0 Token 组合扫描、两阶段 AI 报告和最近 7 次复盘；
- 组合扫描按共同截止日计算 5/10/20/60 日趋势、相对强弱、回撤、波动、盈亏贡献、
  集中度、相关性覆盖和持仓强弱，并提供约 252 个交易日的历史诊断重放；
- DeepSeek 与 GPT 共用观点隔离流程；DeepSeek 默认 Flash、可全局切 Pro，GPT 默认
  `gpt-5.6-sol`。历史诊断按当前持仓数量
  静态回看，不是包含真实仓位变化、交易、现金、费用和分红的收益回测。
- 右下角 AI 助手可选图或直接粘贴 PNG/JPG 截图。带图时复用持仓截图识别页已保存的
  千问 Key/Base URL，由千问生成自由格式的图片观察记录，再由 DeepSeek 解读；原图和
  观察记录均不写入 SQLite，后续追问也不重复发送原图。无图聊天仍只调用 DeepSeek。

## 必须保持的边界

- 不擅自修改 `YEARS`、PE/PB 字段、分位算法、负值/空值处理、前复权、风险评分、
  数据源或 API 字段含义；
- 不把 Key、Cookie、Token 或密码写入代码、测试、日志和文档；
- 不删除或覆盖 `data/monitor.db`，测试必须使用临时数据库；
- 不重写项目或破坏 `app.py`、`agent.py`、`monitor.py` 及三个批处理入口；
- 分钟盯盘不得调用大模型，AI 只允许按需触发、缓存和记录用量；
- 不把概念标签当作主营收入事实，也不把日内概况或分时相对强弱当作买卖信号；
- 修改现有功能前先区分“已实现、已验证、待验证”，不要把静态检查当作浏览器验收。
