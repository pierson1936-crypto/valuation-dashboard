# 项目背景与功能边界

## 项目目的

从代码和旧说明可确认：项目把分散的公开市场数据聚合到一个本地页面，帮助用户用同一
入口查看估值分位、技术指标、资金流和规则化风险信息，减少逐站查询与手工计算。
最初开发动机、目标用户画像和使用频率仍待用户补充。

## 主要场景

1. 输入 6 位股票、ETF 或指数代码，查看单标的分析。
2. 保存自选代码并批量刷新价格和涨跌。
3. 查看大盘指数和板块 ETF 的当日强弱。
4. 把完整分析导出为 Excel。
5. 提供 Key 后，让模型基于工具返回的数字解释或比较标的。
6. 本地持续盯盘自选股，用用户确认的确定性规则记录事件并发送通知。

## 当前指标

- 股票估值：PE-TTM、PB、两者最长近 5 年历史分位和统计区间；
- 行业比较：正 PE/正 PB 样本的行业中位数、正 PE 相对位置；
- 价格：前复权日 K、近 5 年价格分位、区间高低和距高低点；
- 技术：MA、RSI(14)、MACD、布林带、量比、年化波动率、最大回撤；
- 财务：EPS、加权 ROE、毛利率、资产负债率、营收同比；
- 资金：近 5 日主力及不同订单规模净流；
- 派生结果：异动提醒、规则报告和风险评分。

## 核心边界

- 只支持代码可被现有沪深/北交所前缀规则或东方财富搜索识别的标的。
- ETF/指数当前不取指数估值，只用价格历史分位作为代理观察。
- 历史分位是样本内中位秩，不是预测，也不是买卖建议。
- “近 5 年”是最大目标窗口；实际上游样本可能更短，K 线和估值序列各自的起止日、
  样本数也可能不同。
- 数据按需从免费公开接口读取；项目不保证接口服务等级或长期字段稳定。
- AI 只消费本地分析结果并组织文字，核心数值不由模型计算。
- 盯盘模块可保存用户主动录入的持仓数量和成本，但不连接券商、账户或交易接口。
- 没有自动交易能力；AI 草案不自动启用。

## 暂不支持

- 港美股、基金净值体系和跨市场统一口径；
- 指数/ETF 成分穿透后的 PE/PB；
- 完整历史回测、官方交易日历和数据版本审计；
- 用户系统、云端部署、多租户权限和服务端密钥托管；
- 自动交易、收益预测和投资推荐。

## 功能修改建议（本轮未实施）

| 优先级 | 建议 | 价值与前置确认 |
| --- | --- | --- |
| P1 | 明确“实时现价”和“最近收盘分位”的双时间戳，或选择一致的重算口径 | 避免一个响应中价格与分位看似同刻；需用户确认业务口径 |
| P1 | 增加数据来源状态和降级标记 | 用户能区分腾讯主源、新浪兜底、缓存命中和字段缺失 |
| P1 | 将 API Key 改为环境变量/系统凭据优先，并对外部文本统一转义 | 降低浏览器本地 Key 与前端注入风险 |
| P1 | 恢复 TLS 校验，必要时只对已验证的兼容问题做定向处理 | 提升外部请求可信度；先做三数据源兼容测试 |
| P2 | 在结果中展示样本起止日、有效 PE/PB 样本数和负值数量 | 让分位口径可解释，尤其适用于亏损周期 |
| P2 | 给外部请求结果增加来源时间、失败原因和手动强制刷新语义 | 降低缓存与实时数据混淆 |
| P2 | Excel 导出复用当前缓存/结果快照 | 保证页面和导出同一时点，减少重复抓取 |
| P2 | 增加代码搜索和标的类型确认，再进入完整查询 | 避免仅凭代码前缀兜底造成类型误判 |
| P3 | 自托管或固定 ECharts 资源并提供离线降级 | 改善离线可用性和供应链可控性 |
| P3 | AI 多维分析显示每次调用状态、取消与部分成功结果 | 长请求更可控；不影响基础分析 |
