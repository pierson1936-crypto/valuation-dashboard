# 保守整理方案

更新时间：2026-07-28

> 历史说明：本文件记录盯盘模块加入前的项目审计和清理依据。当前架构、文件和测试
> 状态以 `CURRENT_STATUS.md`、`ARCHITECTURE.md`、`FILE_MAP.md` 为准。

## 1. 当前架构概览

项目是一个仅监听本机的 Python Web 应用。`app.py` 同时包含：

- 东方财富、腾讯证券、新浪财经的数据访问；
- PE-TTM、PB、价格分位及技术指标计算；
- 进程内缓存、规则报告、Excel 导出和 AI 编排；
- `ThreadingHTTPServer` 接口和完整的内嵌 HTML/CSS/JavaScript。

审计当时的真实入口为 `启动.bat -> python app.py`；命令行 AI 入口为
`启动AI助手.bat -> python agent.py -> import app`。当时项目没有数据库、数据迁移、
定时任务或独立前端构建流程；之后新增的本地 SQLite 盯盘模块见 `MONITORING.md`。

## 2. 当前目录的主要问题

| 优先级 | 问题 | 影响 |
| --- | --- | --- |
| P0 | 暂未发现会立即导致核心结果系统性错误的已证实问题 | 无 |
| P1 | `app.py` 约 2,320 行，数据访问、计算、接口与前端高度集中 | 修改影响面大，难以定向阅读和测试 |
| P1 | TLS 证书校验被全局关闭 | 外部数据和模型请求存在中间人攻击风险；本轮不直接修改，以免破坏现有接口 |
| P1 | 无正式测试；根目录 `test_*.py` 在导入时直接访问运行中服务 | 测试发现失败、依赖端口和外部状态，不能保护重构 |
| P1 | 页面显示可覆盖为实时价格，但价格分位和规则报告仍基于最近日 K 收盘价 | 同一响应内“显示价格”和“分位口径”可能不完全同刻 |
| P1 | 页面把模型文本和部分外部字段写入 `innerHTML`，同时浏览器保存 API Key | 若外部内容异常，存在前端注入和 Key 暴露风险 |
| P2 | UI 固定写“近 5 年”，但上游可能只返回更短 K 线；K 线与估值样本范围也不同 | 用户可能误以为所有指标都使用完整且相同的 5 年样本 |
| P2 | 无依赖清单、`.gitignore`、README、架构和交接文档 | 环境不可复现，后续智能体需要重复扫描 |
| P2 | HTTP 业务错误大多仍返回 200，异常文本可能直接返回前端 | 调用方难以区分成功与失败，内部错误暴露过多 |
| P2 | `build_excel()` 绕过 180 秒分析缓存重新抓取 | 页面结果与导出结果可能来自不同请求时点 |
| P2 | 端口、样本年限、缓存时长和模型配置集中在 `app.py` | 配置散落；但样本年限属于业务口径，本轮不移动 |
| P2 | 启动脚本首次运行会直接安装依赖 | 环境变化不透明，离线或受限网络下启动失败 |
| P3 | 调试输出、一次性修补脚本、重复说明和过时架构图留在根目录 | 根目录噪声大，容易误导维护者 |

## 4. 文件迁移和删除映射

| 现有内容 | 处理 | 理由 |
| --- | --- | --- |
| `app.py`、`agent.py` | 原位保留 | 真实核心与兼容入口 |
| `启动.bat`、`启动AI助手.bat` | 原位保留 | 用户可见兼容入口 |
| `test_get.py`、`test_raw.py`、`test_server.py` | 由 `tests/test_http.py` 替代后删除 | 导入即联网，不是隔离测试 |
| `check_html.py`、`quick_check.py` | 由正式 HTTP/页面冒烟测试替代后删除 | 针对旧 UI 标记的一次性检查 |
| `fix_bottom.py` | 删除 | 会直接重写 `app.py` 的一次性修补脚本，当前无调用方 |
| `使用说明.md`、`AI助手说明.md` | 信息合并到 `README.md` 后删除 | 内容重复且部分描述已过时 |
| `Agent架构关系图.png` | 由 `ARCHITECTURE.md` Mermaid 图替代后删除 | 只覆盖 AI 投研团，且 Key 链路描述不严谨 |
| `__pycache__/` | 删除并忽略 | 生成缓存 |
| `.agents/` | 空目录，删除 | 无内容且根目录将提供 `AGENTS.md` |
| `.codex/` | 不作为业务代码，加入忽略 | 本地 Codex 环境元数据 |

删除前已用全仓引用搜索确认：除旧说明文档互相引用外，生产代码和启动入口均不
引用上述一次性脚本、旧说明或 PNG。

## 5. 分阶段实施

1. 建立 `.gitignore`、依赖清单和正式 `unittest` 冒烟测试。
2. 运行固定数据分析、HTTP 接口、导入和语法检查，确认输出结构。
3. 建设根 README、AGENTS 和职责明确的交接文档。
4. 删除已被测试或文档替代的旧文件和生成缓存。
5. 初始化 Git 元数据但不自动提交，检查状态、敏感模式、旧引用和文档命令。
6. 启动本地服务，验证旧入口语义、推荐命令、页面和至少一个接口。

## 6. 影响与回滚

- 本轮不修改估值、分位、技术指标、风险评分、接口字段或外部数据源。
- 测试通过 Mock 固定数据，不频繁访问真实外部 API。
- 删除对象均是已确认无生产引用的辅助文件或已被新文档替代的说明。
- 当前目录原先不是 Git 仓库，无法依靠历史提交回滚；实施前记录核心文件
  SHA-256，且不改动 `app.py`、`agent.py` 和批处理入口，可直接保留原业务行为。
- 新增文档、测试、忽略规则和依赖清单可逐文件删除回滚，不影响运行。

## 7. 此次不应修改

- `YEARS = 5`、`KLINE_N = 1300` 及日期截取规则；
- `percentile_rank()` 的中位秩算法及 `None`/负值处理；
- PE-TTM、PB、行业正值样本口径；
- 日 K 前复权方式、数据源优先级和接口字段；
- 规则报告、风险评分、技术指标公式；
- API 响应字段、前端展示含义和现有端口；
- 框架、数据库和模型供应商。

## 8. 待用户确认

- PE/PB 历史分位是否应继续纳入负值；目前代码会纳入，行业中位数则只取正值。
- 实时价格覆盖后，分位与报告是否应同步按实时价重算或明确标注“收盘口径”。
- ETF/指数是否未来需要引入指数级 PE/PB；当前只提供价格历史分位。
- API Key 是否改为仅由环境变量或系统凭据保存，取消浏览器本地存储。
- TLS 校验恢复前，三个行情源在目标 Windows 环境中的证书兼容情况。

## 9. 优先级

- 本轮必须：测试基线、依赖/忽略规则、文档、根目录清理、启动与页面验收。
- 下一步优先：TLS 与前端注入风险、实时价/收盘分位口径一致性、标准 HTTP 状态。
- 可以后做：按实际变更频率把 `app.py` 拆为数据访问、计算和 Web 三个模块。
- 暂时不要做：更换框架、数据源、模型、数据库或重写前端。
