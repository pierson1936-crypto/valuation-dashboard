# 自选股盯盘使用说明

## 最简单的用法

每个标的只需要确定三个价格：

- **关注价**：价格回落到这里时，提醒重新查看买入逻辑；
- **风险价**：价格跌到这里时，提醒复核风险和原有判断；
- **目标价（可选）**：价格涨到这里时，提醒复核兑现条件。

启动 `app.py` 后，在 `http://127.0.0.1:8688/` 打开“盯盘”标签，可以直接保存
三线、启动/暂停后台监控并查看最近提醒。页面关闭后，只要 Web 服务进程仍运行，
后台监控就会继续；Web 服务退出、电脑休眠或关机后停止。

保存三线后，点击标的右侧的铃铛按钮可以预览“风险价触发时会收到什么”。预览只读取
已经保存的风险价规则，不请求实时行情，不写入最近提醒，不发送微信或控制台通知，也
不调用 AI。预览结果只在当前网页中显示，刷新页面后消失。

## 持仓逻辑转化

“盯盘”页的“持仓逻辑转化”保留三个输入：

- **买入 / 持有逻辑**：只写自己已经采用的理由和明确数字；
- **失效条件**：哪些情况出现后，原判断不再成立；
- **复核事项**：提醒触发后需要核实的内容。

“保存逻辑”只写入本地 SQLite；“AI 整理规则”使用页面顶部保存的 DeepSeek Key，
最多返回 3 条核心草案。草案不会自动启用；其中明确的价格规则可以点击“填入三线”，
用户核对后仍需手工保存三线。

基础模式不会读取或发送 RSI、MACD、波动率和估值等高级分析数据，只能整理原文中的
明确价格、涨跌幅和涨跌额。行业利润、产品价格、财报/现金流归入定期复核；行业景气、
放量和持续周期等当前不能稳定分钟执行的条件归入人工复核。

逻辑描述没有明确价格或阈值时，逻辑卡仍显示保存成功，自动规则为 0 条；系统每轮只
提出一个关键问题。用户同意后，程序可以读取历史日线识别前低并生成一条待确认风险价
草案。这个步骤为本地确定性计算、0 Token，且不会写入或启用正式规则。

最近提醒右侧的 AI 图标用于手动复核单条事件。它只读取该事件和对应逻辑卡，不自动
读取新闻或新增行情，不修改规则。相同事件和相同逻辑卡默认缓存 7 天；逻辑卡变化后
缓存键随之变化。

CLI 也使用同一数据库：

```powershell
python -X utf8 monitor.py quick-setup 600519 `
  --name 贵州茅台 `
  --watch-price 1100 `
  --risk-price 1000 `
  --target-price 1400
```

系统同时自动开启当日涨跌幅 `±3%` 异动提醒。连续确认、重复通知抑制、恢复条件、
交易时段等细节由系统处理，不需要逐项配置。

目标价还没确定时可以省略：

```powershell
python -X utf8 monitor.py quick-setup 600519 `
  --name 贵州茅台 `
  --watch-price 1100 `
  --risk-price 1000
```

同一代码再次执行 `quick-setup` 会更新三线和异动预设，不会删除手工创建的高级规则，
也不会清空已有持仓数量、成本和备注。省略目标价会移除之前的目标价预设。

查看目前设置：

```powershell
python -X utf8 monitor.py overview
```

启动盯盘：

```powershell
python -X utf8 monitor.py watch
```

也可以双击 `启动盯盘.bat`。窗口关闭、电脑休眠或关机后，盯盘会停止；目前还没有
远程服务器常驻。

## 提醒代表什么

提醒是“需要重新检查”的信号，不是自动买卖指令：

| 提醒 | 建议查看的内容 |
| --- | --- |
| 到达关注价 | 原买入理由是否仍成立，估值和基本面是否变化 |
| 到达风险价 | 风险假设是否被破坏，是否出现此前未考虑的信息 |
| 到达目标价 | 原目标是否兑现，后续空间与风险是否改变 |
| 当日涨跌异动 | 公告、行业消息、成交和市场整体是否出现异常 |

系统不会接入券商、不会自动下单，也不会预测收益。

## 微信通知

### 个人微信：Server酱

在 Server酱绑定微信并取得 SendKey 后，在启动盯盘的同一个 PowerShell 窗口设置：

```powershell
$env:MONITOR_SERVERCHAN_SENDKEY = Read-Host "请输入 Server酱 SendKey"
python -X utf8 monitor.py test-notify
python -X utf8 monitor.py test-notify --yes
```

第一条测试命令只显示渠道；带 `--yes` 才会真实发送。SendKey 不会写入数据库或
项目文件。

### 企业微信群机器人

```powershell
$env:MONITOR_WECOM_WEBHOOK_URL = Read-Host "请输入企业微信群机器人 Webhook"
python -X utf8 monitor.py test-notify --yes
```

个人微信没有采用模拟登录或非官方机器人协议，以避免封号和稳定性风险。后续部署服务
器时可以继续复用 Server酱或企业微信群机器人。

## Token 和运行成本

- 每分钟行情检查只执行本地确定性规则，**Token 消耗为 0**；
- 三线和自动异动只需要轻量实时报价，不会每分钟做完整估值分析；
- AI 仅在手工执行 `suggest-rules` 时调用一次；
- 网页中的风险提醒模拟预览不调用 AI，Token 消耗为 0；
- 事件复核只在手工点击时调用，默认每天最多 5 次、估算总量不超过 8000 Token；
- 相同事件和逻辑卡 7 天内直接读缓存，缓存命中为 0 Token；
- 相同模型、代码和逻辑的 AI 草案缓存 7 天；
- AI 草案最多给 3 条核心规则，默认不自动启用。
- 草案必须返回严格 JSON；所有含糊阈值写入 `needs_confirmation`，缺少可验证数字时
  返回空规则，不允许模型自行补齐。

需要 AI 帮助梳理买卖逻辑时：

```powershell
$env:DEEPSEEK_API_KEY = Read-Host "请输入 DeepSeek API Key"
python -X utf8 monitor.py suggest-rules 600519 `
  --logic "回落到合理价格时关注，跌破风险底线时提醒，达到目标区间时复核"
```

确认 AI 给出的价格后，再用 `quick-setup` 保存。AI 不参与分钟轮询。

## 本地数据和清理

默认数据库是 `data/monitor.db`，数据只保存在本机并已被 Git 忽略。

| 数据 | 默认保留 | 用途 |
| --- | --- | --- |
| 分钟行情快照 | 7 天 | 短期排查和近期变化，自动清理 |
| 每日指标快照 | 长期 | 避免重复抓取完整分析 |
| 三线、规则、自选、持仓 | 直到手工删除 | 跨重启保留用户设置 |
| 触发事件 | 365 天 | 查看历史提醒 |
| AI 规则草案 | 7 天 | 避免相同请求重复消耗 Token |
| 持仓逻辑卡 | 直到删除标的 | 保存原逻辑、失效条件和复核事项 |
| AI 事件复核 | 7 天 | 同一事件和逻辑卡去重 |
| AI 每日用量 | 90 天 | 执行调用次数和 Token 上限 |
| 通知重试任务 | 跟随事件 | 只重试失败的外部渠道 |
| Web 分析缓存 | 180 秒 | 仅内存，重启即消失 |

所以，七天前的**分钟行情**默认会清理；七天前的每日汇总不会自动删除。每日指标是
SQLite 本地持久数据，不只是内存缓存。

查看数据量和保留策略：

```powershell
python -X utf8 monitor.py status
python -X utf8 monitor.py cleanup
```

## 查看历史提醒

```powershell
python -X utf8 monitor.py events --limit 30
python -X utf8 monitor.py digest --days 1
```

## 高级模式

只有明确需要估值分位、RSI、MACD、资金流或自定义组合时，才建议使用高级规则：

```powershell
python -X utf8 monitor.py add-rule 600519 `
  --name "PE 分位复核" `
  --direction buy `
  --metric pe_percentile `
  --operator lte `
  --threshold 20 `
  --confirm 2 `
  --cooldown-minutes 60 `
  --hysteresis 2
```

完整规则用 `list` 查看，并可用 `enable-rule`、`disable-rule`、`delete-rule` 管理。
`quick-setup` 只替换名称带 `[三线]` 或 `[自动异动]` 的系统预设，不碰这些高级规则。

## 当前限制

- 支持读取 `data/trading_calendar.json`，但项目不内置未经核实的节假日日期；文件
  缺失时使用普通工作日兜底。格式参考 `docs/examples/trading_calendar.json`；
- 免费行情接口不保证秒级实时性或服务等级，不适合自动交易；
- 分钟快照使用本机观察时间，上游报价时间尚未统一；
- Web 已支持三线设置、运行控制和事件查看；高级规则仍由 CLI 管理；
- 通知失败会按渠道进入本地重试队列，默认最多 3 次、间隔指数递增；真实微信渠道仍
  需在本机完成发送和失败恢复验收。
