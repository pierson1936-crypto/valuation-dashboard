# 自选股盯盘使用说明

## 最简单的用法

每个标的只需要确定三个价格：

- **关注价**：价格回落到这里时，提醒重新查看买入逻辑；
- **风险价**：价格跌到这里时，提醒复核风险和原有判断；
- **目标价（可选）**：价格涨到这里时，提醒复核兑现条件。

启动 `app.py` 后，在 `http://127.0.0.1:8688/` 打开“盯盘”标签，可以直接保存
三线、启动/暂停后台监控并查看最近提醒。页面关闭后，只要 Web 服务进程仍运行，
后台监控就会继续；Web 服务退出、电脑休眠或关机后停止。

## 持仓截图导入

“自选”页切换到“持仓”后，可以把 PNG/JPG 持仓截图直接从微信聊天窗口拖入，也可
点击拖放区选择文件。页面先本地预览，只有点击“发送千问识别”才会把截图传给阿里云
百炼。需要单独填写千问 API Key 和百炼控制台显示的完整 Workspace Base URL；它们
不复用页面顶部的 DeepSeek Key。部分微信版本若拖拽时不提供标准图片文件，页面会提示
先把图片另存到本机后再拖入。

识别结果只进入校对表，不会直接写库。代码、名称、数量或成本价模糊时会保留空值并
标记“重点核对”；全部补齐并点击“确认写入”后，才更新本地持仓。同代码的数量和成本
会更新，截图中没出现的旧持仓不会自动删除，已有规则、备注和启停状态不会被覆盖。

截图原图、API Key 和 Base URL 不写入 SQLite。相同图片和模型的结构化识别结果缓存
7 天，命中缓存不调用模型。截图识别是手工动作，不进入分钟盯盘。

## 持仓扫描与可选 AI 报告

“持仓”页应先执行不需要 Key 的“持仓扫描分析”。程序并发复用现有持仓、
`analyze_cached`、`market_overview` 和 15 分钟多日市场缓存，在共同数据截止日上计算：

- 5/10/20/60 日组合趋势、相对沪深300和可用板块代理的强弱；
- 当前累计盈亏来源，以及按期初组合市值计算的近期价格贡献；
- 仓位、行业、重叠主题和高波动资产集中度；
- 最近 60 个共同收益日的持仓相关性、有效配对覆盖和高相关连通组；
- 各持仓的强势、震荡、转弱、弱势分类，以及当前最需要关注的少数问题。

这一步全部由确定性代码完成，Token 消耗为 0。缺少完整窗口、近期行情有长缺口、共同
截止日明显滞后或组合覆盖不足时，相关结论显示“数据不足”，不会用可分析子集冒充完整
组合，也不会把缺失数据排成低风险。

扫描还提供最近约 252 个交易日、每 5 日取样的历史诊断重放。每个历史状态只使用当时
及以前的数据，再观察随后 5/10 日表现；组合曲线按当前持仓数量静态回看。它不包含
真实历史仓位、买卖、现金、手续费、税费、分红和调仓，不是交易策略收益回测。

需要文字解释时，“我的当前判断”为必填自由文本，不使用固定模板。用户可选择
DeepSeek 或 GPT。DeepSeek 复用页面顶部的全局 Flash/Pro 选择，GPT 默认
`gpt-5.6-sol`。原文先写入本地 `portfolio_reports` 并锁定；
第一轮模型只读取程序生成的组合快照，看不到用户判断；第二轮才读取锁定原文、第一轮
独立分析和从同一快照提取的精简确定性事实，生成一致点、分歧点和可能遗漏。

独立分析不按固定指标顺序输出，而是从给定事实中选择最重要的 2 至 5 个问题。每项必须
区分已确认事实、基于数据的有限推断和缺失信息；不得补充新闻、公告、用户买入理由或
未来预测，也不得重算程序给出的确定性指标。

其中“已确认事实”不接受模型自由填写。程序先为可引用事实生成稳定证据 ID；模型只能
返回这些 ID，服务端验证后再还原为确定性事实文字。未知 ID 会直接使报告失败，但不会
限制模型自由选择哪些问题最重要，也不会固定问题顺序。

DeepSeek 使用兼容 `/chat/completions`、JSON 输出、零随机度并显式关闭 thinking；GPT
使用 Responses API、低 reasoning、`store:false` 和 JSON 输出。第一阶段上限 3200
Token，第二阶段上限 1800 Token；第二阶段不重复发送技术、资金流和财务明细。系统不
自动重试截断响应，避免一次点击产生额外调用。

DeepSeek 模型选择只允许 `deepseek-v4-flash` 和 `deepseek-v4-pro`，每次手工请求显式
传递并在后端再次校验。持仓报告、规则草案和事件复核的缓存键包含实际模型，Flash 与
Pro 不会互相复用缓存；返回结果保存并展示实际模型。分钟盯盘不读取该选择，也不调用模型。

一次完整报告通常包含两次模型调用。程序在第一轮前原子预留 2 次调用与保守 Token；
任一阶段失败后，按实际已返回调用数和可得 Token 结算，避免失败调用误记为 0。默认只
记录用量、不设置应用层上限；用户设置
`MONITOR_PORTFOLIO_REPORT_DAILY_CALL_LIMIT` 或
`MONITOR_PORTFOLIO_REPORT_DAILY_TOKEN_LIMIT` 为正整数后才启用保护。

相同供应商、模型、组合快照和判断缓存 7 天。页面只在手工点击时调用模型，不进入分钟
盯盘；“最近 7 次分析”只列成功报告，失败和未完成记录不占复盘名额。成功复盘记录不因
缓存过期而消失，超过 7 次后才清理更早的成功报告。

保存三线后，点击标的右侧的铃铛按钮可以预览“风险价触发时会收到什么”。预览只读取
已经保存的风险价规则，不请求实时行情，不写入最近提醒，不发送微信或控制台通知，也
不调用 AI。预览结果只在当前网页中显示，刷新页面后消失。

## 持仓逻辑转化

“盯盘”页的“持仓逻辑转化”保留三个输入：

- **买入 / 持有逻辑**：只写自己已经采用的理由和明确数字；
- **失效条件**：哪些情况出现后，原判断不再成立；
- **复核事项**：提醒触发后需要核实的内容。

“保存逻辑”只写入本地 SQLite；“AI 整理规则”使用页面顶部保存的 DeepSeek Key，
最多返回 3 条核心草案。草案不会自动启用；其中明确的价格规则可以点击“填入三线”，
用户核对后仍需手工保存三线。

基础模式不会读取或发送 RSI、MACD、波动率和估值等高级分析数据，只能整理原文中的
明确价格、涨跌幅和涨跌额。行业利润、产品价格、财报/现金流归入定期复核；行业景气、
放量和持续周期等当前不能稳定分钟执行的条件归入人工复核。

逻辑描述没有明确价格或阈值时，逻辑卡仍显示保存成功，自动规则为 0 条；系统每轮只
提出一个关键问题。用户同意后，程序可以读取历史日线识别前低并生成一条待确认风险价
草案。这个步骤为本地确定性计算、0 Token，且不会写入或启用正式规则。

最近提醒右侧的 AI 图标用于手动复核单条事件。它只读取该事件和对应逻辑卡，不自动
读取新闻或新增行情，不修改规则。相同事件和相同逻辑卡默认缓存 7 天；逻辑卡变化后
缓存键随之变化。

CLI 也使用同一数据库：

```powershell
python -X utf8 monitor.py quick-setup 600519 `
  --name 贵州茅台 `
  --watch-price 1100 `
  --risk-price 1000 `
  --target-price 1400
```

系统同时自动开启当日涨跌幅 `±3%` 异动提醒。连续确认、重复通知抑制、恢复条件、
交易时段等细节由系统处理，不需要逐项配置。

目标价还没确定时可以省略：

```powershell
python -X utf8 monitor.py quick-setup 600519 `
  --name 贵州茅台 `
  --watch-price 1100 `
  --risk-price 1000
```

同一代码再次执行 `quick-setup` 会更新三线和异动预设，不会删除手工创建的高级规则，
也不会清空已有持仓数量、成本和备注。省略目标价会移除之前的目标价预设。

查看目前设置：

```powershell
python -X utf8 monitor.py overview
```

启动盯盘：

```powershell
python -X utf8 monitor.py watch
```

也可以双击 `启动盯盘.bat`。窗口关闭、电脑休眠或关机后，盯盘会停止；目前还没有
远程服务器常驻。

## 提醒代表什么

提醒是“需要重新检查”的信号，不是自动买卖指令：

| 提醒 | 建议查看的内容 |
| --- | --- |
| 到达关注价 | 原买入理由是否仍成立，估值和基本面是否变化 |
| 到达风险价 | 风险假设是否被破坏，是否出现此前未考虑的信息 |
| 到达目标价 | 原目标是否兑现，后续空间与风险是否改变 |
| 当日涨跌异动 | 公告、行业消息、成交和市场整体是否出现异常 |

系统不会接入券商、不会自动下单，也不会预测收益。

## 微信通知

### 个人微信：Server酱

在 Server酱绑定微信并取得 SendKey 后，在启动盯盘的同一个 PowerShell 窗口设置：

```powershell
$env:MONITOR_SERVERCHAN_SENDKEY = Read-Host "请输入 Server酱 SendKey"
python -X utf8 monitor.py test-notify
python -X utf8 monitor.py test-notify --yes
```

第一条测试命令只显示渠道；带 `--yes` 才会真实发送。SendKey 不会写入数据库或
项目文件。

### 企业微信群机器人

```powershell
$env:MONITOR_WECOM_WEBHOOK_URL = Read-Host "请输入企业微信群机器人 Webhook"
python -X utf8 monitor.py test-notify --yes
```

个人微信没有采用模拟登录或非官方机器人协议，以避免封号和稳定性风险。后续部署服务
器时可以继续复用 Server酱或企业微信群机器人。

## Token 和运行成本

- 每分钟行情检查只执行本地确定性规则，**Token 消耗为 0**；
- 三线和自动异动只需要轻量实时报价，不会每分钟做完整估值分析；
- 持仓扫描和历史诊断重放只执行确定性代码，Token 消耗为 0；
- 规则草案、事件复核、截图识别和持仓报告都只在用户手工触发时调用模型；
- 一次完整持仓报告通常调用两次模型，缓存命中为 0 Token；
- 网页中的风险提醒模拟预览不调用 AI，Token 消耗为 0；
- 事件复核只在手工点击时调用，默认只记录调用和 Token，不设置应用层额度；
- 相同事件和逻辑卡 7 天内直接读缓存，缓存命中为 0 Token；
- 相同模型、代码和逻辑的 AI 草案缓存 7 天；
- 相同截图和视觉模型的持仓识别结果缓存 7 天；缓存命中为 0 Token；
- AI 草案最多给 3 条核心规则，默认不自动启用。
- 草案必须返回严格 JSON；所有含糊阈值写入 `needs_confirmation`，缺少可验证数字时
  返回空规则，不允许模型自行补齐。

需要 AI 帮助梳理买卖逻辑时：

```powershell
$env:DEEPSEEK_API_KEY = Read-Host "请输入 DeepSeek API Key"
python -X utf8 monitor.py suggest-rules 600519 `
  --logic "回落到合理价格时关注，跌破风险底线时提醒，达到目标区间时复核"
```

确认 AI 给出的价格后，再用 `quick-setup` 保存。AI 不参与分钟轮询。

## 本地数据和清理

默认数据库是 `data/monitor.db`，数据只保存在本机并已被 Git 忽略。

| 数据 | 默认保留 | 用途 |
| --- | --- | --- |
| 分钟行情快照 | 7 天 | 短期排查和近期变化，自动清理 |
| 每日指标快照 | 长期 | 避免重复抓取完整分析 |
| 三线、规则、自选、持仓 | 直到手工删除 | 跨重启保留用户设置 |
| 触发事件 | 365 天 | 查看历史提醒 |
| AI 规则草案 | 7 天 | 避免相同请求重复消耗 Token |
| 持仓截图识别结果 | 7 天 | 只保存图片哈希和结构化 JSON，不保存原图或凭据 |
| AI 持仓报告 | 缓存 7 天；复盘保留最近 7 次成功报告 | 保存锁定判断、独立分析和观点对比 |
| 持仓逻辑卡 | 直到删除标的 | 保存原逻辑、失效条件和复核事项 |
| AI 事件复核 | 7 天 | 同一事件和逻辑卡去重 |
| AI 每日用量 | 90 天 | 记录调用次数和 Token；默认不阻止按需模型请求 |
| 通知重试任务 | 跟随事件 | 只重试失败的外部渠道 |
| Web 分析缓存 | 180 秒 | 仅内存，重启即消失 |

所以，七天前的**分钟行情**默认会清理；七天前的每日汇总不会自动删除。每日指标是
SQLite 本地持久数据，不只是内存缓存。

查看数据量和保留策略：

```powershell
python -X utf8 monitor.py status
python -X utf8 monitor.py cleanup
```

## 高级模式

只有明确需要估值分位、RSI、MACD、资金流或自定义组合时，才建议使用高级规则：

```powershell
python -X utf8 monitor.py add-rule 600519 `
  --name "PE 分位复核" `
  --direction buy `
  --metric pe_percentile `
  --operator lte `
  --threshold 20 `
  --confirm 2 `
  --cooldown-minutes 60 `
  --hysteresis 2
```

完整规则用 `list` 查看，并可用 `enable-rule`、`disable-rule`、`delete-rule` 管理。
`quick-setup` 只替换名称带 `[三线]` 或 `[自动异动]` 的系统预设，不碰这些高级规则。

## 当前限制

- 支持读取 `data/trading_calendar.json`，但项目不内置未经核实的节假日日期；文件
  缺失时使用普通工作日兜底。格式参考 `docs/examples/trading_calendar.json`；
- 免费行情接口不保证秒级实时性或服务等级，不适合自动交易；
- 分钟快照使用本机观察时间，上游报价时间尚未统一；
- Web 已支持三线设置、运行控制和事件查看；高级规则仍由 CLI 管理；
- 通知失败会按渠道进入本地重试队列，默认最多 3 次、间隔指数递增；真实微信渠道仍
  需在本机完成发送和失败恢复验收。
