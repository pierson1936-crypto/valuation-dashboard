# 技术决策记录

## 2026-07-28：保留单文件核心和兼容入口

- 决策：本轮不拆分 `app.py`，保留 `python app.py`、当时已有的两个批处理和
  `agent.py`；后续盯盘新增了第三个批处理入口。
- 原因：核心虽高度集中，但现有回归保护刚建立；大规模搬迁的风险高于当前收益。
- 后续：只有在测试覆盖具体边界后，才按数据访问、计算、Web/前端逐步拆分。

## 2026-07-28：不改金融计算和数据字段

- 决策：保留 5 年样本、中位秩分位、PE/PB 负值处理、行业正值样本和前复权数据。
- 原因：这些是用户明确禁止擅改的业务口径；代码中没有足够证据说明应替换。
- 历史采用这些口径的产品原因：待用户确认。

## 2026-07-28：不引入数据库和前端框架

- 决策：继续使用进程内 TTL 缓存和内嵌前端。
- 原因：当前没有持久化需求或迁移证据；换数据库/框架会扩大部署和兼容成本。

## 2026-07-28：测试采用标准库和固定数据

- 决策：使用 `unittest`、Mock 和随机本机端口，不增加测试依赖。
- 原因：项目规模小，核心依赖接近零；固定数据能稳定保护输出，避免频繁访问免费接口。

## 2026-07-28：删除旧辅助材料

- 决策：正式测试和新文档就位后，删除根目录一次性修补/字符串检查脚本、重复说明和
  过时 PNG。
- 原因：这些文件无生产引用，部分会在导入时联网或直接改写核心文件，容易误导下一个
  维护者；有效信息已分别迁移到 README、测试和架构文档。

## 保留但待复核的历史选择

- 东方财富/腾讯/新浪作为数据源的最初选择原因：从代码只能确认其免费公开接口和兜底
  关系，其他历史原因待用户确认。
- DeepSeek 默认模型和可选 OpenAI 首席：现有功能配置，供应商与模型有效性需随实际
  账号和上游文档复核。
- 全局关闭 TLS 校验：历史兼容原因待确认；这是风险记录，不代表继续认可该做法。

## 2026-07-28：盯盘引入本地 SQLite

- 决策：新增 `data/monitor.db`，但不改变现有 Web 分析接口和内存缓存。
- 原因：规则状态、去重、持仓、事件和跨重启数据必须持久化；此时数据库已有明确需求。
- 保留：分钟数据 7 天、事件 365 天、AI 草案 7 天；每日快照和用户配置长期保留。

## 2026-07-28：分钟循环禁止调用大模型

- 决策：确定性规则负责每分钟判断；AI 只在用户执行 `suggest-rules` 时调用。
- 原因：避免持续 Token 成本、模型波动和不可审计触发。
- 兼容：草案使用白名单校验并缓存 7 天，且永不自动写入启用规则。

## 2026-07-28：微信采用官方/中继通知适配

- 决策：支持企业微信群机器人和 Server酱，不实现个人微信模拟登录。
- 原因：个人微信非官方机器人不稳定且有账号风险；通知凭据只从环境变量读取。

## 2026-07-28：普通用户采用三线盯盘

- 决策：主流程只让用户设置关注价、风险价和可选目标价，并自动添加 `±3%` 日内
  异动提醒；确认、冷却、回差和交易时段由系统管理。
- 原因：散户在设置阶段同时判断大量指标和控制参数会产生认知负担，三个价格更适合
  用于“到点复核”，而不是制造更多交易结论。
- 兼容：高级 `add-rule` 保留为次级入口；重复快速设置只替换系统预设，不删除手工
  规则。AI 草案最多 3 条，且不自动启用。

## 2026-07-29：规则草案使用严格输入和严格 JSON

- 决策：模型只能整理用户明确给出的阈值；缺少数字时返回空规则和
  `needs_confirmation`，不得从分析数据或常识补齐买卖线。
- 校验：拒绝 Markdown 包裹、JSON 外文字、缺少顶层字段或规则必填字段的输出。
- 渐进确认：逻辑卡保存与自动规则生成分别报告；每轮最多一个问题。用户明确同意后，
  程序才从历史日线识别前低并生成待确认价格草案，仍不写入正式规则。
- 数据边界：基础模式不调用完整分析器，也不向模型发送 RSI、MACD、波动率或估值；
  行业、产品、财报和当前不能稳定分钟执行的条件归入人工/定期复核。
- 缓存：Prompt 版本升级为 `strict-v4-staged`，不复用旧约束生成的 7 天缓存。

## 2026-08-04：持仓报告采用真正的两阶段观点隔离

- 决策：用户判断先持久化并锁定；第一轮模型请求只包含结构化组合快照，第二轮才
  同时读取用户原文、独立结果和从同一快照提取的精简确定性事实。
- 原因：把用户判断和持仓数据放入同一次提示词，即使要求模型“先忽略”，也不能证明
  独立分析未受锚定影响。
- 输出：第一轮自行选择 2 至 5 个重要问题，并区分事实、推断和缺失信息；第二轮只用
  同一快照提取的精简确定性事实做一致点、分歧点和可能遗漏的对照。
- 边界：复用现有行情与分析缓存，不增加新闻或其他数据源；完整报告为两次按需调用，
  7 天缓存；按需模型功能默认只记录用量、不限制额度，只有用户显式设置正数
  环境变量时才启用保护，且都不进入分钟盯盘。

## 2026-08-05：组合结论先由确定性代码计算，AI 只做解释

- 决策：`monitoring/portfolio_analysis.py` 负责共同截止日、5/10/20/60 日趋势、相对
  强弱、回撤、波动、仓位贡献、集中度、相关性、覆盖率和强弱分类；这些结果不交给模型
  自行重算。
- 原因：组合指标必须可复现、可测试并明确处理停牌、缺失和覆盖不足；模型更适合从给定
  事实中选择少数重要问题、解释有限推断，并指出仍缺少的信息。
- 输出：无 Key 时也可执行完整确定性扫描，Token 为 0；AI 不采用统一段落模板，但严格
  限制事实来源和 JSON 字段，避免把自由表达误解为自由编造。
- 事实绑定：程序为可确认事实生成稳定 `evidence_id`；模型只选择 ID，服务端校验并还原
  展示文字。模型仍可自由选择问题和组织有限推断，但不能把自由文本直接标成已确认事实。

## 2026-08-05：首版采用历史诊断重放，不冒充完整收益回测

- 决策：最近约 252 个交易日每 5 日取样，只使用观察日及以前数据形成状态，再统计随后
  5/10 日表现；按当前持仓数量静态回看。
- 边界：不包含真实历史仓位、买卖、现金、手续费、税费、分红和调仓，也没有交易策略
  或参数优化，因此只叫“历史诊断重放（非交易回测）”。
- 后续：先用真实持仓体验其解释价值，再决定是否值得引入完整账户流水和策略假设。

## 2026-08-05：持仓报告支持双供应商并一次性预留两阶段额度

- 决策：DeepSeek 使用兼容 `/chat/completions` 并关闭 thinking；GPT 使用 Responses API、
  低 reasoning、`store:false`，默认 `gpt-5.6-sol`。
- 成本边界：首轮前原子预留 2 次调用与保守 Token，任一阶段失败后按实际已返回调用数和
  可得 Token 结算；相同供应商、模型、快照和判断缓存 7 天。
- 兼容：旧多维分析后端接口暂时保留，但页面入口下线，不继续维护为主要产品能力。

## 2026-08-05：DeepSeek 采用受控全局双模型切换

- 决策：网页顶部只提供 V4 Flash 与 V4 Pro，下游手工 AI 请求显式携带模型，后端再次
  按白名单校验；未选择时使用白名单内的 `AGENT_MODEL`，默认 Flash。
- 原因：满足用户按额度和任务强度切换的需求，同时避免任意模型字符串造成接口漂移、
  缓存污染和不可解释的成本变化。
- 缓存与展示：持仓报告、规则草案和事件复核按实际模型分缓存并返回实际模型；分钟盯盘
  不读取选择、不调用模型。GPT 仍是独立可选供应商，默认 `gpt-5.6-sol`。

## 2026-08-12：单标的与大盘采用“固定事实，开放分析”

- 决策：程序只整理连续编号的原始数据事实，不把规则报告、风险理由或提醒结论预先写进
  单标的 AI 输入；模型自行选择 2 至 5 个重点、组织顺序和表达。大盘报告同样不规定固定
  栏目，由模型自行识别当前指数与板块之间的主要结构和矛盾。
- 事实边界：涉及数据时必须引用 `[[E01]]` 形式的编号。服务端拒绝未知编号，并只把本次
  实际引用的事实返回页面，避免模型把自由生成的文字冒充已经确认的数据。
- 原因：把分析栏目和结论全部写死会压缩模型发现不同重点的空间；完全放开事实来源又会
  增加编造风险。因此只约束“依据是什么”，不预先规定“必须得出什么结论”。

## 2026-08-12：分时第一版聚焦相对强弱并减少指标噪音

- 决策：单标的页面按需读取标的与参考指数截至查询时点的当日分钟行情，按昨收归一后
  展示相对强弱、标的均价和成交量。股票按上市板块选择市场指数；ETF 优先通用匹配公开
  跟踪指数，匹配失败时回退沪深 300，不维护固定 ETF 代码特例。
- 隔离与缓存：分时走独立接口，失败不影响主分析；成功缓存 60 秒，失败缓存 15 秒。
- AI 边界：模型只接收分时摘要和最多 8 个代表时点，不发送整条分钟序列。第一版不做
  历史分时、复杂形态、龙头股组合或盘中买卖提示。
- 降噪：从页面和当前分析消费者撤下买一/卖一与布林带；布林底层计算和响应字段暂时
  保留兼容。本决定不修改 PE/PB、分位、负值处理、前复权、风险评分或数据字段口径。
